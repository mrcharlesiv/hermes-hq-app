# Direct-chat message hint: verification

`python3 windows/tests/test_direct_composer_fit.py -v` links the production fitter, both model entry points and both direct-page key handlers to inert receivers. It needs .NET 9 and the app's pinned WinUI package in the local NuGet cache. The replay lays out the actual XAML track/spacing declarations with the Commands, Attach and Send controls, using controlled proportional font measurements. It checks the default TextBox placeholder's span, padding and border against the installed SDK template. All editor, selection and focus results from this command are **managed receiver results**, not Windows measurements or key delivery.

## Native acceptance — supervisor, exact candidate only

Use the same isolated synthetic direct chat (`Trip planning`, `Sonnet 5`, query `food`, `2 of 2`). Keep the original 1028 × 779 capture surface. Constrain the chat pane's parent, **not** the editor and not the outer window. Keep Find and transcript untouched. Record source/build identity, run/attempt, original PNG digests, actual pane and editor/presenter bounds, insets, DPI, app and OS text scales alongside each frame. Wait for stable layout and confirm the same page/window before and after capture.

| Light, standard text | Frozen Windows before | Required on the new Windows build |
|---|---|---|
| 252 px pane | `101-chat-find-narrow.png`: four clipped bands over 15 px of ink; chip visible; box 96 px high | The complete word `Message` on one line, no ellipsis and no chip. The empty box stays a single row, without displacing the transcript for clipped text. |
| 767 px pane | `102-chat-find-expanded.png`: `Message Trip planning`, one 137 px ink band; chip visible; box 42 px high | Full hint and full chip as before on return to wide. No extra row. |

Inspect originals at 1:1. Measure hint ink **inside the actual empty presenter**, excluding controls/caret, and the border on an unobstructed vertical. Record ink bands, width and box height on both sides. The old 15 px was painted ink, **not** the allocated editor width. Confirm the actual words and whether the chip is painted; a one-band count by itself would pass for `M`. At normal size compare the narrow box's height to the candidate's expanded single-row control. Do not substitute Mac heights, predicted widths or recreated images for after pixels.

- Repeat wide → narrow → wide and the reverse, with both controls installed initially, no current model/no options, options only, a long model and a long chat title. Repeat with larger **Windows text**, separate from app zoom. At fixed outer width, sweep the *measured final hint space* through one unit below, exactly at, and one above the full natural label width. Below: `Message`; at/above: full title. Check the shortcut independently at its measured fit limit; it must give way before clipping either its title or `Message`. At large text, if the short word cannot fit inline even without the chip, the same editor gets the full row.
- For input use a separate owned, offline fixture whose send/mic/model/system actions cannot execute. Verify target **before** any input; refuse global or unconfined key injection. Tab into `chat.composer`; type ordinary characters and Shift+Enter to form a wrapping multiline draft. Partially select across the newline. Resize repeatedly in both directions, including a transition into and out of the full-row layout. Record the actual key/edit events, editor/peer identity, UTF-16 value and selection range, focused element, focus ring and UIA Name `Message` at every stop. Type another character: it must replace exactly that selection. Clear only the fixture draft and confirm the correct hint returns. Assigning `Text`, or selecting `oo` in Find, does **not** prove typing.
- In the no-effect receiver, the visible chip and **Chat Actions → Model** must resolve to the same current-chat Models picker request. In the native narrow view confirm keyboard reachability of that alternative without making a model choice. Record zero sends, mic starts, model changes and system activations.

No new native originals or witnessed input means the native gate remains open. A light result is not dark, Narrator, whole-chat or full visual-parity signoff.
